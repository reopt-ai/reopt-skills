# This is NOT the SDK you know

`@reopt-ai/brandapp-sdk` ships frequent breaking changes that may differ from your training data. It ships docs at top-level `docs/` (not `dist/docs/`) — read the relevant guide in `node_modules/@reopt-ai/brandapp-sdk/docs/` before writing or reviewing any code. Heed deprecation notices.

## Doc map

`api-reference.md` is the combined surface (SDK init, user-scoped auth, EAV, webhooks, service token, React hooks, AI); the rest are topic files. **`docs/` documents no Better Auth wiring** — that lives in the package `README.md`.

## Hard rules

- **Env namespace (2.0+):** `BRANDAPP_*` = your credentials. `REOPT_*` = platform hosts (rarely set). `BRANDAPP_SDK_*` = behavior toggles. `NEXT_PUBLIC_BRANDAPP_*` = browser-safe subset. No `REOPT_CLIENT_*` / `REOPT_BRANDAPP_ID` / `REOPT_WEBHOOK_SECRET` / `REOPT_SDK_*` / `NEXT_PUBLIC_REOPT_*` / `NEXT_PUBLIC_EAV_HASH` aliases — 2.0 dropped them.
- `BRANDAPP_ID` = brandappId (app), not brandId (brand). MCP `reopt_brandapp_list` looks it up.
- `BETTER_AUTH_URL` must match the browser-facing origin exactly.
- `@reopt-ai/*` installs from public npm — never add a GitHub Packages scope or token. Remove only the exact legacy project-level `@reopt-ai:registry=https://npm.pkg.github.com` entry; preserve unrelated registry/auth settings and ask before changing user/global npm config.
- Never put `NODE_TLS_REJECT_UNAUTHORIZED=0` in `.env` — script-scope only. Never in production.
- `createReoptAdapter` / `createReoptOAuth` / `createReoptBetterAuth` throw in browser runtimes. Server-only (`import "server-only"`).
- `cms` is read-only from 1.8+ — `posts.create/update/delete` and `tags.create` are gone. Content authoring lives in Reopt Studio.
- Split hosts: main API `brandapp.reopt.ai` (1.10+), auth `id.reopt.ai` (auto-derived from the main host). Don't hardcode `www.reopt.ai`; the older `brand.reopt.ai` is legacy.
- `isReoptSDKError()` over `instanceof ReoptSDKError` — bundle-safe across SDK copies.
- **Auth credential (3.0):** a short-lived Bearer `token` takes precedence and makes `clientId`/`clientSecret` optional (token-only config — the safe client-side mode). **Never ship `clientSecret` to the browser** — `createReoptSDK` / `createBrandappProvider` throw `CONFIG_BROWSER_SECRET`. For client-side use, mint a scoped token server-side (`POST /api/v1/brandapp/{id}/token/mint`) and pass `{ token }`.
- **Better Auth 1.7 (4.0, breaking):** the peer is `better-auth@^1.7.1` — 1.6 and below do not work. There is no client plugin any more: `createReoptOAuthClient()` and `signIn.oauth2({ providerId })` are **removed**. Use `signInWithReopt(authClient, { callbackURL })` / `linkReoptAccount(authClient)` from `@reopt-ai/brandapp-sdk/better-auth/client` (thin wrappers over `signIn.social({ provider: "reopt" })` / `linkSocial()`), and drop `oauth2.link()`.
- **Callback path moved (4.0):** the Reopt callback is now `${baseURL}/api/auth/callback/reopt` (1.6: `/api/auth/oauth2/callback/reopt`). Reopt system brandapp clients have both registered, but a self-registered redirect URI must add the new path (exact match) **before** upgrading.
- **Token endpoint auth (4.0):** the SDK sends `client_secret_post` — the Reopt brandapp client default. The 1.7 authorization server rejects credentials sent with a method other than the registered one; a client registered as `client_secret_basic` must pass `createReoptOAuth({ tokenEndpointAuthMethod: "client_secret_basic" })`.
- **`signOut()` stays app-local (4.0):** better-auth 1.7 would redirect generic-OAuth `signOut()` to the OP `end_session_endpoint`, and most Reopt clients may not initiate logout ("The client is not allowed to initiate logout"). The SDK sets `disableProviderLogout` by default. Opt in with `createReoptOAuth({ providerLogout: true | { postLogoutRedirectURI } })` only for a client with `enableEndSession` + a registered post-logout URI; otherwise end the Reopt session through `@reopt-ai/brandapp-sdk/logout`.
- **Account namespace (4.0):** PKCE follows the better-auth default (on), and the discovered `issuer` becomes `account.issuer` — keep `idBaseUrl` **stable across deploys** or existing users resolve as brand-new accounts. 1.6-era account rows need no consumer-side backfill; the Reopt API records the issuer on first lookup.
- **Remote adapter (4.0):** `createReoptAdapter()` delegates 1.7's two required atomic operations — `consumeOne` (read-and-delete a single row, e.g. one-time tokens) and `incrementOne` (guarded counter increment) — to the Reopt API. An `Unsupported operation` response means the Reopt-side deployment is behind; do not hand-roll a local fallback.
- **Webhooks (3.0+/3.4+):** `verifySignature(timestamp, body, signature, secret)` signs `"{timestamp}.{body}"`; headers are `x-reopt-signature: sha256=<hex>` + `x-reopt-timestamp`. Events are `contactCreated` / `contactUpdated` / `contactDeleted` / `workflowRunCompleted` / `workflowRunFailed` plus `subscriptionActivated` / `subscriptionRenewed` / `subscriptionCanceled` / `subscriptionPaymentFailed`. Old dotted names silently never fire. Subscription delivery is workspace-scoped: filter `data.brandappId`; honor `accessUntil` on cancellation.
- **Removed deprecated aliases (3.0):** `ReoptAdapterConfig` / `ReoptEavConfig` → `ReoptSDKConfig`; `ReoptAdapterError` → `ReoptSDKError`. Rename only.
- **Mutations aren't retried by default (2.2+):** POST/PATCH skip retry on 5xx / network / timeout (dup-write / dup-credit guard); 429 always retries; opt in with `config.retryNonIdempotent`. An `Idempotency-Key` is sent for server-side dedup.
- AI streaming `config.timeout` is an **idle** (between-chunk) gap, not wall-clock (2.2+). Streaming 402 surfaces as `CreditLimitError`; AI SDK provider errors are `APICallError` (2.3+).
- Large EAV `backfill` batches via `bulkUpdate` (2.2+) — tune `BackfillOptions.batchSize`; don't hand-roll per-record update loops.
- The in-memory dev server refuses to start under `NODE_ENV=production` (3.0) unless `REOPT_DEV_SERVER_ALLOW_PRODUCTION=1`. `trace` debug now also redacts camelCase token keys (`accessToken` / `refreshToken` / `idToken` / `clientSecret`).
- **Plans hosted checkout (3.4+ current server):** redirect to the `createCheckout` URL; the hosted order-review page shows server-truth plan details and collects required-terms consent before payment. `RequiredTermsError` is older-server compatibility only. Live Paddle uses the same flow; only a priced live Toss plan returns 409 `LIVE_MODE_UNSUPPORTED`. `plans.cancel` covers sandbox/Paddle/Toss/IAP and keeps access through `accessUntil`; `getCheckout` never re-exposes the capability URL.
- **Consent lives in `sdk.terms`, and terms are brand-owned (2026-08-03).** The same terms bind the Brandapp and the brandfront, so do not keep a per-app copy of the text or a private consent table. `list` needs no user token; `consent` / `withdraw` / `listMyConsents` take the user's Bearer token. Checkout is separate — the hosted order-review page collects required consent, so do not add your own pre-checkout gate.
- **Push tokens are self-scoped (`sdk.push`).** `registerDeviceToken` / `unregisterDeviceToken` / `listDevices` all act on the signed-in customer via their Bearer token, and `listDevices` never returns raw tokens. Do not hand-roll `/push/me/tokens` calls or store device tokens beside your own user table.
- **Files (3.5+):** use folder CRUD, file rename/move, `readContent`, and `usage` rather than inventing a parallel file-manager API. Treat `STORAGE_LIMIT`, `FOLDER_NOT_EMPTY`, `CONTENT_TOO_LARGE`, and `UNSUPPORTED_CONTENT_TYPE` by code; read `docs/files.md`.
- **EAV list projection (3.6+):** pass attribute IDs in `select` for wide list views; omitted `select` preserves all values. Do not call the option `attributes` or apply client-side deletion after over-fetching.
- **EAV concurrency + TTL (4.2+):** every record carries `version`; pass it back as `records.update(entityId, id, { ifVersion })` and handle 412 `PreconditionFailedError` by re-reading — never add your own version attribute or a read-modify-write loop. Use `increments: { [attributeId]: delta }` for counters/balances (server-side atomic; `values` may be omitted) instead of computing the new number on the client. Use `expiresAt` (ISO 8601, client-computed absolute time; `null` clears) for claims/leases/queues — an expired record disappears from reads, `count`, and unique checks, and a server cron deletes it hourly — instead of a cleanup cron of your own. Filters that cannot narrow via an index (`neq` / `not_in` / `after` / `before`, custom-attribute sorts) over more than 10,000 candidate rows are refused with 422 `QUERY_TOO_BROAD`; lead with `eq` / `in` / `authUserId`.
- **Analytics bridge (4.1+):** `startBrandappAnalytics(sdk)` from `@reopt-ai/brandapp-sdk/analytics` fetches the brand's reopt-data `baseUrl` / `writeKey` and calls `init` once; it returns `null` when the brand has no Data project, so `?.` every call. It imports the optional peer **`@reopt-ai/data-sdk`** (that exact, npm-deprecated name — not `data-sdk-client`); install it only in code paths that use the subpath, and do not hand-roll the config fetch.
- **OIDC Single Logout (3.2+, additive, `@reopt-ai/brandapp-sdk/logout`):** end sessions in both directions. Receive: mount `createBackchannelLogoutHandler({ onLogout: async ({ sid, sub }) => … })` at a stable URL registered as the OAuth client's `backchannel_logout_uri`; make `onLogout` idempotent (reopt retries). Trigger: `buildEndSessionUrl({ idToken, postLogoutRedirectUri, state })` for RP-initiated logout (`postLogoutRedirectUri` must be pre-registered). Persist the `id_token` `sid` claim at login so `onLogout` can delete the matching sessions. Never hand-roll `logout_token` verification (`verifyBackchannelLogoutToken` covers custom transports/tests). Signature is Web Crypto Ed25519 (no deps). 3.3 returns HTTP 503 (retryable) — not 400 — for transient discovery/JWKS failures. Read `docs/logout.md`.
